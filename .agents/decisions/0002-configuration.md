# Current game configuration and source execution

`src/model/game/games.py` locates the packaged `src/games/` configurations; each game package assembles `Configuration` from Python `board.py`, `rules/`, `pieces/`, `quests/`, `clocks/` and exporter modules. `src/model/game/configuration.py` loads modules with `importlib` and exposes copying/renaming/deletion of configuration directories. `src/model/game/source_validation.py` validates editable Python by executing it, and `src/view/code_editor.py` is reachable from settings. This **is the current implementation**, not the approved target JSON-only model.

Pure helpers from that archived implementation have now been restored as `src/model/game/schema.py`, `conditions.py`, `hooks.py`, `capture_policy.py`, `definition.py` and `snapshot_queries.py`. The current versioned validator loads bundled `config.json` resources through `importlib.resources.files("games")` and a strict bounded directory identifier, **without importing individual game subpackages**. It enforces schema-v2/strict-key/type/bound contracts and returns recursively immutable `GameDefinition` data. Source-controlled JSON for chess and English draughts is present under `src/games/`; both definitions remain `playable: false`. The new `SnapshotQueries` module copies and bounds finite JSON facts, rejects missing/untrusted inputs, and can provide a registered trusted query to `RuleProgram` without mutating session state. `capture_policy.EvaluationBudget` applies shared bounded work reservations with atomic parent/child rejection; `RuleProgram.evaluate` accepts that budget during declarative rule evaluation. `capture_geometry.CaptureEnumerator` enumerates bounded single and sequential captures against an unmodified board projection, including both short-range and flying geometry. These remain isolated foundations, not working GUI gameplay. The active desktop runtime does not yet read them. They define bounded JSON validation, trusted read-only condition evaluation and immutable effect proposals; none mutates the board or replaces the active Python-loaded `Configuration` or legacy `GameManager` yet. Replacing that runtime is the next integration boundary.

The archived #405 engine instead used validated schema-versioned JSON definitions, bounded conditions/hooks, immutable snapshots, revisioned actions and event replay. Those capabilities are absent from the present desktop working tree and must be integrated into one authoritative engine before replacing source editing. Requirements and architecture will be updated within #271 as the code is actually changed.
