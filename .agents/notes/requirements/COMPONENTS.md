# COMPONENTS — BoardGamesWithQuests

## 1. Technology and schema choice

| Responsibility | Authoritative implementation |
|---|---|
| Routing/UI | Wouter, React, TypeScript, Bun, Rsbuild, Tailwind CSS, shadcn/ui, Motion |
| Rendering | Generic SVG scene, typed visual templates and asset grants |
| Native | Tauri 2 WebView loading production HTTPS frontend, platform signing |
| API | Python FastAPI/Pydantic (separate Vercel project), cookie session, Origin/CSRF |
| Engine | Pure Python functional interpreter, no database/network dependencies |
| Database schema | **Prisma schema (PSL), build-time tooling**, tooling-only package |
| Runtime DB client | Python psycopg, not Prisma |
| Database and identity | Supabase PostgreSQL, Auth, private Broadcast, Storage |
| Migrations | Reviewed SQL generated by Prisma Migrate plus PostgreSQL-only constraints/triggers in INTEGRITY.sql |
| API contract | OpenAPI 3.1 YAML and FastAPI conforming Pydantic models |
| Tests | pytest (engine/API/DB), Playwright (browser), native smoke checks |
| Documentation | Python docstrings, **TSDoc**, Rustdoc and OpenAPI summaries |

Supabase PostgreSQL is modeled in **Prisma Schema Language** (`SCHEMA.prisma`), with SQL reserved for capabilities Prisma cannot declare (`INTEGRITY.sql`). Prisma is a **schema/migration tool only**; the authoritative engine and database access remain Python/psycopg. The managed `auth.users` table remains outside Prisma migrations, and its foreign-key constraints are added without altering Supabase-managed schemas.

The API and web deployments are separate Vercel projects; the web origin forwards `/api/*` to FastAPI. Native applications load that same HTTPS origin. Supabase owns Auth, relational state and Storage. Configurations are portable JSON, never the database's authoritative document format.

## 3. Package boundaries

`SCHEMA.prisma` declares all database models/enums/relations/indexes; `packages/database` owns Prisma Migrate tooling. `packages/server/api` authenticates, authorizes, projects and transactionally persists; `engine` evaluates actions in pure immutable contexts; `configuration` imports/exports/validates JSON; `server/supabase` declares exceptional SQL routines, Auth/RealtIme policies, and data seed declarations. `packages/web` contains the only React UI and Wouter routes, including all concrete pages, the generic renderer and editor. `packages/native` is an HTTPS WebView wrapper only.

`INTEGRITY.sql` is the specification of authored SQL that Prisma cannot express (including cross-schema Supabase Auth foreign keys), while `packages/server/supabase/security.sql` implements the applicable routines: security grants/policies, publication immutability triggers and private revision broadcasts. Prisma-generated versioned SQL migrations remain reviewed deployment artifacts. `seed.sql` contains registry/reference DML and Storage bucket initialization, never authoritative game definitions.
